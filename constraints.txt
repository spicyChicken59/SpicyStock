# The whole resolution pinned: every workflow step that installs
# requirements.txt, and the test suite.
#
# requirements.txt bounds each direct requirement below its next major; this
# file holds every package pip resolves under them, so no release on PyPI --
# a direct one (anthropic 2.0.0, 21 Oct 2026) or one underneath (python-dateutil
# arrives under pandas, matplotlib under mplfinance, pydantic under anthropic
# and alpaca-py) -- changes a night's run without a change here.
#
# Every workflow step that installs requirements.txt (evening, intraday,
# issuer-evidence, morning, source-recovery) installs `-r requirements.txt -c
# constraints.txt`, and requirements-dev.txt carries the -c line, so CI runs the
# suite against the runtime set the evening installs. A constraint only pins: it
# installs nothing that a requirement did not ask for. Two other files are not
# constrained by this one: requirements-host.txt, which pins the morning host's
# whole set, and tools/requirements-historical*.txt, which the historical jobs
# install and which pin their direct requirements only.
#
# Resolved 24 Oct 2026 for CPython 3.12 on Linux x86_64, the platform every one
# of those steps runs on; numpy 2.5.4 and contourpy 1.4.0 need Python 3.12 or
# later, so the file does not install on 3.11. The 44 runtime pins are the set
# the evening workflow's own runner installed in run 40128552858 (Python
# 3.12.15, pip 26.2.1); a clean venv on Python 3.12.3 resolved the same 44 and
# the five the suite adds (iniconfig, pluggy, Pygments, pytest, PyYAML).
#
# Move a pin in its own change and run the suite against it. To re-resolve the
# whole set, at the repository root in a clean CPython 3.12 venv on Linux x86_64
# (the unconstrained copy sits beside requirements.txt, which its -r line names,
# and is removed whether the install succeeds, fails or is interrupted, under
# bash or sh), and paste what it prints below this header in place of the pins.

#   (trap 'rm -f dev-unconstrained.txt' EXIT; trap 'exit 130' INT TERM HUP
